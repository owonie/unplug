## 2. AI 활용 아키텍처

### 2.1 전체 워크플로우

```
┌──────────────────────────────────────────────────────────────┐
│                    AI-Assisted Development Loop                │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ① 기획 의도 전달                                            │
│       ↓                                                      │
│  ② AI 브레인스토밍 (3가지 접근법 → 트레이드오프 분석)          │
│       ↓                                                      │
│  ③ 설계 확정 (시스템 간 인터페이스 정의)                      │
│       ↓                                                      │
│  ④ AI 코드 생성 (Rust WASM + JS 동시 작업)                   │
│       ↓                                                      │
│  ⑤ 빌드 & 테스트 (WASM 컴파일 → 브라우저 검증)               │
│       ↓                                                      │
│  ⑥ AI 디버깅 (에러 메시지 → 근본 원인 분석 → 수정)           │
│       ↓                                                      │
│  ⑦ 반복 (평균 3~5 iteration per feature)                     │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 핵심 의사결정: 왜 Rust WASM + Three.js?

**AI와의 설계 대화 요약:**

> **인간**: "브라우저에서 돌아가는 3D 뱀서류를 만들고 싶어. 기술 스택 추천해줘."
>
> **AI 분석**: 3가지 옵션 제시
> 1. Unity WebGL — 무거움, 로딩 10초+
> 2. Phaser3 + JS — 2D만 가능, 3D 확장 어려움
> 3. **Rust WASM + Three.js** — 게임 로직은 고성능(Rust), 렌더링은 유연(Three.js)
>
> **결론**: WASM이 게임 루프/물리/AI를 60fps에서 처리, Three.js는 3D 렌더링 담당. 관심사 분리 완벽.

## 3. 핵심 프롬프트 예시 (5개)

### 프롬프트 #1: 50 클래스 밸런스 테이블 설계

```
"4원소(화/빙/뇌/독) 조합으로 50개 클래스를 설계해줘.
조건:
- Tier 1 (15개): 순수 4 + 하이브리드2 6 + 하이브리드3 4 + 쿼드 1
- Tier 2 (20개): 각 Tier1에서 분기, 원소 심화
- Tier 3 (10개): 최종 특화, 히든 포함
- 전직 조건: Tier1=Lv3+오브2, Tier2=Lv5+오브5, Tier3=Lv8+오브8
- 각 클래스에 스킬 3개 (Active/Passive/Ultimate)
- 밸런스: Pure > 단일 딜링, Hybrid > 유틸리티, Quad > 범용"
```

**결과**: 45개 일반 클래스 + 5개 히든 클래스, 150개 스킬 데이터 테이블 생성 (class_data.rs 280줄, skill_data.rs 900줄)

### 프롬프트 #2: 제스처 인식 알고리즘

```
"마우스 드래그로 3가지 제스처를 구분하는 알고리즘 설계:
1. 바깥 드래그 (플레이어→외부): 방향 공격
2. 안쪽 드래그 (외부→플레이어): 쉴드
3. 원 그리기 (340°+ 회전): 궁극기
조건: 오탐율 <5%, 반응시간 <100ms, 좌/우클릭 구분"
```

**결과**: 각도 누적 방식으로 원 감지, 드래그 벡터로 방향 판별. JS에서 mousedown→mousemove→mouseup 이벤트 체인으로 구현.

### 프롬프트 #3: 보스 3페이즈 전투 설계

```
"10웨이브마다 등장하는 보스를 3페이즈로 설계:
- 필드 소거 후 1:1 결투 느낌
- 각 페이즈마다 공격 패턴 변화
- 페이즈 전환 시 연출 (카메라 셰이크 + 텍스트)
- 난이도: 숙련 플레이어가 2~3분 걸리는 수준"
```

**결과**: HP 임계값 기반 3페이즈 (66%/33%), 각 페이즈별 이동 패턴(추적/원형/공격적), 넉백 저항 90%, 등장 연출 시퀀스 구현.

### 프롬프트 #4: WASM 메모리 OOM 디버깅

```
"wasm-pack build 성공하는데, 브라우저에서 5분 플레이 후 OOM 크래시.
증상: enemy Vec이 계속 증가, GC가 안 되는 것 같음.
현재 코드: [world.rs의 spawn/death 로직 첨부]"
```

**AI 진단**: `enemies.retain(|e| e.alive)` 호출 위치가 death 이벤트 발생 전이라, 죽은 적이 Vec에 계속 남아있었음. → `finalize_deaths()` 패턴으로 리팩토링, 매 프레임 명시적 GC 추가.

### 프롬프트 #5: 패시브 아이템 시너지 시스템

```
"Vampire Survivors처럼 패시브 아이템 12개를 설계하되:
- 레벨업 선택지에 기존 원소/스탯과 혼합 등장
- 중복 획득 시 레벨업 (최대 Lv5)
- 아이템끼리 시너지 (ex: 흡혈+버서커 = 저HP시 흡혈 3배)
- 리스크-리워드 밸런스 (Phoenix Feather: 부활 but 1회용)"
```

**결과**: item_data.rs 258줄, ItemInventory 시스템, 12개 아이템 각각 독립적 보너스 계산, World 통합.

## 5. AI 한계 및 인간 개입 사례

### 5.1 AI가 틀린 것들

| 상황 | AI 실수 | 인간 수정 |
|------|---------|----------|
| WASM 빌드 | `wasm-bindgen` 버전 호환성 오류 생성 | Cargo.toml 버전 고정으로 해결 |
| Three.js 카메라 | lookAt + 셰이크 동시 적용 시 떨림 | lookAt은 셰이크 제외하고 적용 |
| 적 AI | 무한 루프 패턴 생성 (적이 벽에 갇힘) | 맵 경계 wrap + 거리 기반 제거 |
| 사운드 | AudioContext 자동 재생 차단 미고려 | 유저 인터랙션 후 resume() 추가 |
| 밸런스 | 선형 스케일링으로 난이도 톱니파 | 시그모이드(S-커브) 기반으로 교체 |

### 5.2 핵심 교훈

> **AI는 "0→80%" 생성기이고, 인간은 "80%→100%" 완성자이다.**
>
> AI가 생성한 코드의 약 60%는 그대로 사용 가능했지만, 나머지 40%는:
> - 에지 케이스 미처리 (죽은 적 참조, 빈 Vec 인덱싱)
> - 브라우저 환경 특수성 미반영 (AudioContext, WebGL 제한)
> - 게임 "느낌"의 미세 조정 (히트스톱 0.04초 vs 0.08초 차이)
>
> **결론**: AI를 맹신하지 않고, 도구로서 통제하며, 핵심 의사결정은 인간이 한다.

## 6. 기술 스택 상세

### 6.1 Rust WASM 엔진 구조

```
crate/src/
├── lib.rs          — WASM 바인딩 (GameEngine ↔ JS)
├── game/
│   ├── world.rs    — 게임 월드 (1100줄, 모든 시스템 통합)
│   ├── player.rs   — 플레이어 (스탯, 대시, 스킬)
│   ├── enemy.rs    — 적 AI (9종, S-커브 스케일링)
│   ├── class_data.rs — 50 클래스 정의
│   ├── skill_data.rs — 150 스킬 정의
│   ├── item_data.rs  — 12 패시브 아이템
│   └── wave_event.rs — 웨이브 이벤트 (리스크-리워드)
├── engine/         — 물리, 충돌
└── ai/             — 적 행동 패턴
```

### 6.2 프론트엔드 구조

```
web/src/
├── renderer.js  — Three.js 코어 (카메라, 씬, 풀링) — 737줄
├── vfx.js       — VFX 모듈 (파티클, 이펙트) — 285줄
└── sound.js     — 사운드 매니저 (BGM + SFX)
```
